# MC68882 Mode Upgrade Plan

## Context

The MC68881 FPGA implementation is feature-complete (48 opcodes, CIR protocol, FSAVE/FRESTORE, 349 tests). The goal is to add full MC68882 compatibility via a compile-time generic `fpu_version_g`, covering three areas:

1. **FSAVE/FRESTORE frame format** — Different format words and frame sizes (OS-visible)
2. **Pending instruction pipeline** — The 68882's key performance feature: accept a second instruction while the first is still executing
3. **Clock speed target** — Nice-to-have: target 50 MHz (68882 max) vs current 33 MHz

The 68881 and 68882 share identical instruction sets, registers, bus protocol, exception handling, and FMOVECR constants. The differences are architectural (pipeline depth, frame size) not functional.

## 68881 vs 68882 Frame Formats

| Frame | 68881 FW | 68881 Size | 68882 FW | 68882 Size | Delta |
| ----- | -------- | ---------- | -------- | ---------- | ----- |
| Null  | `$0000`  | 0B (0W)    | `$0000`  | 0B (0W)    | same  |
| Idle  | `$0018`  | 24B (6W)   | `$0038`  | 56B (14W)  | +8W   |
| Busy  | `$00B4`  | 180B (45W) | `$00D4`  | 212B (53W) | +8W   |

## 68882 Pending Instruction Pipeline

The 68882's key architectural feature: while ALU executes instruction N, the CIR bus interface can accept opword + command + operands for instruction N+1. When N completes, N+1 starts automatically — no CPU busy-wait polling loop.

Current 68881 behavior during CIR_EXECUTE:
- Response CIR returns BUSY (`$0000`)
- CPU must poll Response CIR until FPU is idle
- New opword writes are ignored (FSM not in CIR_IDLE)

Target 68882 behavior during CIR_EXECUTE:
- If no pending instruction queued: accept new opword+command, respond with TRANSFER/NULL
- CPU sends operand data → stored in pending staging buffer
- When ALU completes instruction N: auto-launch pending instruction N+1
- If pending already queued: respond BUSY (only 1-deep queue)

Scope: only cpGEN (arithmetic/move) instructions can be pipelined. cpCond/cpSAVE/cpRESTORE always wait for ALU idle.

**3b. CIR_SAVE_FRAME data mux** (lines 3205-3257): Add 8 extra words for pending instruction state. Content of the extra words:

| Word Offset | Content | Purpose |
| ----------- | ------- | ------- |
| +0 (idle 6, busy 45) | `pending_valid_reg & "000..." & pending_opword_reg` | Pending valid flag + opword |
| +1 (idle 7, busy 46) | `pending_command_reg & pending_src_fmt_reg & pending_instr_type & ...` | Pending command + decoded fields |
| +2 (idle 8, busy 47) | `pending_operand_staging(31 downto 0)` | Pending operand word 0 |
| +3 (idle 9, busy 48) | `pending_operand_staging(63 downto 32)` | Pending operand word 1 |
| +4 (idle 10, busy 49) | `pending_operand_staging(95 downto 64)` | Pending operand word 2 |
| +5 (idle 11, busy 50) | `pending_instaddr_reg` | Pending FPIAR |
| +6 (idle 12, busy 51) | `pending_dst/src_reg_idx & pending_direction & pending_reg_to_reg & ...` | Pending decoded metadata |
| +7 (idle 13, busy 52) | `(others => '0')` | Reserved |

In 68881 mode these cases are unreachable (word count < 45/6) and optimized away.

### Phase 5: Pending Instruction Pipeline (68882 mode)

**File:** `src/mc68881_top.vhd` — modifications to `cir_dialog_proc`

This is the core 68882 feature. All changes are gated on `fpu_version_g = FPU_68882` (compile-time constant → dead code elimination in 68881 mode).

**5a. CIR_EXECUTE modification** (line 3724): Accept new instruction while ALU busy.

Current logic:
```vhdl
when CIR_EXECUTE =>
  if valid = '1' then
    cir_state_reg <= CIR_EXECUTE_DONE;
  end if;
  -- cpSAVE preemption check
```

New logic (68882 mode):
```vhdl
when CIR_EXECUTE =>
  if valid = '1' then
    cir_state_reg <= CIR_EXECUTE_DONE;
  elsif fpu_version_g = FPU_68882
    and cir_opword_written = '1' and cir_command_written = '1'
    and pending_valid_reg = '0'
    and cir_instr_type = CIR_TYPE_CPGEN then
    -- Accept pending cpGEN instruction
    pending_opword_reg <= cir_opword_reg;
    pending_command_reg <= cir_command_reg;
    pending_instr_type <= cir_instr_type;
    pending_src_fmt_reg <= cir_src_fmt;
    pending_dst_reg_idx_reg <= to_integer(unsigned(cir_command_reg(9 downto 7)));
    pending_src_reg_idx_reg <= to_integer(unsigned(cir_command_reg(12 downto 10)));
    pending_decoded_op <= cir_decode_cpgen_opcode(cir_command_reg);
    pending_reg_to_reg <= cir_command_reg(14);
    pending_direction <= cir_command_reg(13);
    pending_instaddr_reg <= cir_instaddr_reg;
    cir_opword_written <= '0';
    cir_command_written <= '0';
    cir_state_reg <= CIR_PENDING_DECODE;
  end if;
  -- cpSAVE preemption check (unchanged)
```

**5b. New CIR_PENDING_DECODE state**: Mirrors CIR_DECODE but targets pending registers.

```
CIR_PENDING_DECODE:
  if pending_reg_to_reg = '1' then
    -- Reg-to-reg: no operand transfer needed
    pending_valid_reg <= '1';
    cir_state_reg <= CIR_EXECUTE;  -- Return to waiting for ALU
  elsif pending_direction = '0' then
    -- Mem-to-reg: need operand data from CPU
    pending_xfer_word_count <= cir_src_word_count(pending_src_fmt_reg);
    pending_xfer_word_idx <= 0;
    cir_state_reg <= CIR_PENDING_XFER_SRC;
  else
    -- Reg-to-mem: operands come during DST phase after execution
    pending_valid_reg <= '1';
    cir_state_reg <= CIR_EXECUTE;
  end if;
```

**5c. CIR_PENDING_XFER_SRC state**: Accept operand words into pending staging buffer.

```
CIR_PENDING_XFER_SRC:
  -- Check for ALU completion FIRST (takes priority)
  if valid = '1' then
    -- ALU finished while we're still fetching pending operands.
    -- Process completion, then continue pending fetch.
    -- (Handle via pending_valid_reg = '0' still; operands not complete yet)
    cir_state_reg <= CIR_EXECUTE_DONE;
  elsif cir_operand_word_arrived = '1' then
    case pending_xfer_word_idx is
      when 0 => pending_operand_staging(31 downto 0) <= d_in;
      when 1 => pending_operand_staging(63 downto 32) <= d_in;
      when 2 => pending_operand_staging(95 downto 64) <= d_in;
    end case;
    if pending_xfer_word_idx + 1 >= pending_xfer_word_count then
      cir_state_reg <= CIR_PENDING_XFER_SRC_WAIT;
    else
      pending_xfer_word_idx <= pending_xfer_word_idx + 1;
    end if;
  end if;
```

**5d. CIR_PENDING_XFER_SRC_WAIT/WAIT2 states**: Hold cycles for format conversion to settle (mirrors CIR_XFER_SRC_WAIT/WAIT2 pattern).

```
CIR_PENDING_XFER_SRC_WAIT:
  if valid = '1' then
    cir_state_reg <= CIR_EXECUTE_DONE;  -- ALU finished, handle completion first
  else
    cir_state_reg <= CIR_PENDING_XFER_SRC_WAIT2;
  end if;

CIR_PENDING_XFER_SRC_WAIT2:
  pending_valid_reg <= '1';  -- Pending instruction fully staged
  if valid = '1' then
    cir_state_reg <= CIR_EXECUTE_DONE;
  else
    cir_state_reg <= CIR_EXECUTE;  -- Return to waiting for ALU
  end if;
```

**5e. CIR_EXECUTE_DONE modification** (line 3737): Auto-launch pending instruction.

Current: after exception check → CIR_IDLE.

New (68882 mode): after exception check:
```
if no_enabled_exception then
  if pending_valid_reg = '1' then
    -- Swap pending into active and launch
    cir_opword_reg <= pending_opword_reg;
    cir_command_reg <= pending_command_reg;
    -- ... (copy all pending fields to active)
    pending_valid_reg <= '0';
    cir_launch_alu <= '1';  -- Start pending instruction
    if pending_reg_to_reg and op_class = OP_CLASS_MOVE then
      cir_state_reg <= CIR_IDLE;
    elsif pending_direction = '1' then
      cir_state_reg <= CIR_XFER_DST;  -- Reg-to-mem needs output
    else
      cir_state_reg <= CIR_EXECUTE;  -- Wait for ALU again
    end if;
  else
    cir_state_reg <= CIR_IDLE;  -- No pending, back to idle
  end if;
elsif exception_enabled then
  -- Exception: pending instruction stays pending (saved by FSAVE if needed)
  cir_state_reg <= CIR_EXCEPT_POST;
end if;
```

**5f. Response primitive modification** (lines 3922-3958): In 68882 mode during CIR_EXECUTE:

```
when CIR_EXECUTE =>
  if fpu_version_g = FPU_68882 and pending_valid_reg = '0' then
    cir_response_prim <= CIR_PRIM_NULL;  -- "Ready to accept instruction"
  else
    cir_response_prim <= CIR_PRIM_BUSY;
  end if;
```

For CIR_PENDING_XFER_SRC: respond with TRANSFER primitive (operand request) just like CIR_XFER_SRC does.

**5g. Reset and clear logic**: On reset and CIR_RESTORE_FORMAT null frame: clear `pending_valid_reg <= '0'` and all pending registers.

### Phase 10 (Nice-to-Have): Clock Speed Target 50 MHz

The 68882 ran at up to 50 MHz vs the 68881's 25 MHz. Current design closes timing at 33 MHz with WNS=+0.265ns (30.303ns period). Targeting 50 MHz (20ns period) requires ~10ns improvement.

**Approach:**

- Change XDC clock constraint from 30.303ns to 20.0ns
- Run synthesis + implementation to identify new critical paths
- Expected problem areas:
  - Packed decimal scaling path (currently ~17ns in combinational cone)
  - CIR operand staging → format conversion → operand_reg path
  - Trig unit polynomial evaluation datapath
- Mitigation strategies:
  - Add pipeline registers in critical format conversion paths
  - Split packed decimal digit extraction into additional stages
  - Deeper Horner evaluation pipeline (coefficient fetch → multiply → accumulate)
  - May need to increase `alu_latency` for affected operations
- Acceptance: WNS >= 0 at 20.0ns period
- This phase is independent of Phases 1-9 and can be done separately
